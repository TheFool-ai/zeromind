## 服务组织

- 独立应用放在 `apps/<service>/`，拥有自己的源码、测试、迁移、依赖和部署入口。
- 每个服务的 `docs/` 与 `src/` 平级，维护上下文、模型、规则、事件、API 和运维文档。
- 根目录 `docs/` 只维护跨服务关系和项目级约定，避免重复保存领域规则。
- 服务之间通过明确接口或事件交互，不读取对方的数据表或导入内部领域代码。

## 当前起点

先建立订阅服务。已讨论的范围是手动录入、OPML 批量导入、修改、启用和关闭订阅源，以及获取、去重、保存和查询来源条目。

订阅源不保留 `site_url`；文章条目保留原文链接。RSSHub 采用固定部署地址，来源凭据在 RSSHub 容器内配置。

运行管理负责调度、重试、超时和执行记录，后续单独梳理。原文解析、AI 分析、阅读、笔记和分发等领域暂不重建。

归档中的旧设计文档用于历史参考，其中较早的字段、轮询归属和迁移方案不自动成为新项目要求。
