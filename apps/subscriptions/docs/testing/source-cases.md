# 来源管理测试用例

状态：下列场景已有自动化断言，映射见 [覆盖表](coverage.md)。所有 API 场景使用临时已迁移数据库。

| 用例编号 | 功能 | 前置条件 | 操作 | 预期 |
| --- | --- | --- | --- | --- |
| TC-SUB-001-01 | SUB-001 | 空数据库 | 名称含空白、分类重复、地址含默认端口，创建后读详情 | 201、Location 正确；规范化结果持久化 |
| TC-SUB-001-02 | SUB-001 | 已有来源 | 使用规范化后相同地址再次创建 | 409，来源仍仅一条 |
| TC-SUB-001-03 | SUB-001 | 空数据库 | 空名称、超长名称/分类、ftp、凭据 URL、错误类型、未知字段或 null | 422、不写入、不回显测试密码 |
| TC-SUB-002-01 | SUB-002 | 两来源之一关闭 | 筛选关闭状态、limit=1 分页 | 筛选正确、相邻页 ID 不同 |
| TC-SUB-002-02 | SUB-002 | 任意状态 | 非法 UUID、未知 UUID、非法分页或布尔值 | 非法输入 422；不存在详情 404 |
| TC-SUB-003-01 | SUB-003 | 两个不同地址来源 | 同时改名称并将地址改为另一来源地址 | 409，原名称和地址均保留 |
| TC-SUB-003-02 | SUB-003 | 已创建来源 | 改为 RSSHub 地址 | 200，address_version 推进 |
| TC-SUB-003-03 | SUB-003 | 配置已更新 | 使用旧配置版本 PATCH | 409，新配置不被覆盖 |
| TC-SUB-003-04 | SUB-003 | 已创建来源 | 空修改、null、未知字段、非法版本 | 422，数据不变 |
| TC-SUB-003-05 | SUB-003 | 已创建来源 | 只传规范化后相同名称 | 200，配置版本和详情不变 |
| TC-SUB-004-01 | SUB-004 | 启用来源 | 关闭两次再启用 | 重复关闭详情相同，重新启用成功 |
| TC-SUB-004-02 | SUB-004 | 配置已更新 | 用旧配置版本关闭 | 409，状态不变 |
| TC-SUB-004-03 | SUB-004 | UUID 不存在 | 调用启用和关闭 | 404，不创建来源 |

领域层另外验证地址变更重置检查点、改名不使地址版本失效、非法更新不能部分改变内存状态。
仓储层补充真实行版本竞争，API 中的旧配置版本场景不是两个并发 HTTP 请求的压力测试。
