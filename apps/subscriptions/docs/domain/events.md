# 领域事件：候选设计

状态：规划中。当前无事件类型、聚合事件队列、发布器或 Outbox；下表不代表已发布的契约。

| 候选事件 | 触发条件 | 建议最小业务信息 |
| --- | --- | --- |
| SubscriptionCreated | 来源创建成功 | 来源 ID、配置版本 |
| SubscriptionDetailsChanged | 名称或分类真正变化 | 来源 ID、配置版本、变更字段 |
| SubscriptionAddressChanged | 来源地址真正变化 | 来源 ID、地址版本、配置版本 |
| SubscriptionEnabled | 关闭变启用 | 来源 ID、配置版本 |
| SubscriptionDisabled | 启用变关闭 | 来源 ID、配置版本 |
| SubscriptionItemDiscovered | 首次发现并保存条目与修订 1 | 来源 ID、条目 ID、修订号 |
| ItemRevisionAdded | 已有条目内容变化并追加修订 | 来源 ID、条目 ID、修订号 |

以上为本轮整理的候选命名，正式契约需要另行评审。领域事件不直接等于跨服务集成事件。
无内容变化的观察、重复启停和相同配置更新不产生相应变化事件。
获取成功或失败如何通知运行管理属于执行协作契约，不能直接拿条目事件替代运行结果。

实施前需决定：事件 ID、发生时间、schema 版本、聚合版本语义、事务提交与发布关系、订阅者幂等及重放策略。
若采用 Outbox，需要新增迁移和测试；目前 ER 图只有三张业务表，不预画不存在的消息表。
不在事件中携带凭据；是否暴露来源地址和元数据由消费者契约决定。
