# 订阅限界上下文

## 目的

维护“从哪里订阅、是否启用、来源产生了哪些条目与修订”。本服务中的 Subscription 指共享订阅源，不是用户付费订阅或用户关注关系。
当前没有用户、租户、权限或计费模型；不能从现有地址唯一规则推导多租户隔离。

## 职责边界

| 范围 | 内容 | 当前状态 |
| --- | --- | --- |
| 来源管理 | 手动创建、修改、启停、列表和详情 | 已实现 |
| 批量导入 | OPML 解析、来源录入及导入反馈 | 已实现，已有来源跳过 |
| 来源数据 | 条目身份、元数据、不可变修订、条目查询 | 领域和仓储已实现 |
| 获取业务 | 条件请求检查点、地址版本防护、获取后持久化 | 仅检查点领域方法已实现 |
| 外部适配 | HTTP/Feed 解析、固定 RSSHub 配置 | 未实现 |

不负责定时计划、任务租约、运行日志、重试调度、RSSHub 容器管理、原文全文解析、AI 分析、阅读状态、笔记或分发。
来源不存 site_url；文章元数据保留 original_url，两者语义不同。

## 数据所有权与一致性

专属三张表：subscriptions、subscription_items、item_revisions，见 [ER 图](../implementation/er-diagram.md)。
来源地址在当前服务范围唯一；条目身份仅在同一来源、同一身份类型范围唯一。
Subscription 与 SubscriptionItem 分别为聚合根，通过 ID 关联。获取检查点不是任务执行结果，不能表达失败原因、重试次数或执行耗时。
工作单元只保证本库事务一致性，未实现 Outbox 或跨服务消息可靠交付。

## 对外契约

当前公开六个来源管理接口和一个 OPML 导入接口，见 [API](../implementation/api.md)。不公开文章条目查询、采集或事件接口。
运行管理将来发起一次获取请求；订阅上下文校验来源状态和地址版本，负责合法条目的业务处理。具体调用协议待设计。
RSSHub 由用户独立部署，未来适配器读取固定地址；来源凭据在 RSSHub 容器内配置，不建多实例管理中心。

## 安全及尚未解决的问题

当前无鉴权，不宜直接暴露公网。FeedAddress 只校验格式，不保证地址可达或安全。
启用网络采集前必须设计 SSRF、重定向、响应大小、超时与解析限制；不因为格式合法就允许访问任意内网地址。
关闭来源目前只改变 enabled，不会取消尚不存在的运行任务。将来的在途任务取消或丢弃结果规则需显式约定。
