# SUB-005 OPML 批量导入

状态：已实现解析器、应用用例、HTTP 入口及自动化测试。复用现有来源聚合，不新增数据表或导入任务系统。
“已有则跳过”指规范化后 Feed 地址已经存在，不是标题相同、文章内容相同或全文哈希相同。本功能不访问 Feed，不导入文章。

## 输入映射

接受无命名空间的 OPML，根节点 opml，恰好一个 body，至多一个 head；body 中只能嵌套 outline。
带 xmlUrl 或 type 为 rss/atom（不区分大小写）的 outline 视为候选来源；声明 rss/atom 却缺地址逐项失败。
其他文件夹/非 Feed 节点不计入候选总数，没有 Feed 的合法文件返回零项结果。

| OPML 输入 | 来源字段与规则 |
| --- | --- |
| xmlUrl | feed_address，沿用 FeedAddress 规范化 |
| title / text | name，优先非空 title，再 text，均缺失则用规范化地址前 300 字符 |
| 祖先文件夹名称 | 依次作为分类；仅文件夹继承，不将父 Feed 标题当分类 |
| category | 逗号分隔后追加分类，领域规则去空白和去重 |
| htmlUrl | 忽略，不保存 site_url |
| 其他属性 | 不用于启停、任务或凭据配置 |

## 去重与事务

1. 完整解析文件后才开始写入；非法 XML、结构或超限整份拒绝，无部分导入。
2. 地址非法则该条失败；以规范化地址判断重复，不按名称或分类去重。
3. 文件内此前成功创建或确认已存在的地址再次出现，跳过。
4. 库内已有来源跳过，不覆盖名称、分类、地址、检查点、版本或启停。已有来源的导入新名称/分类不再校验。
5. 不存在时创建默认启用的来源，逐项独立事务提交。名称/分类非法只使该条失败；同地址的后续合法项仍可尝试。
6. 查重后并发插入发生唯一冲突，也返回跳过，而不是整批报错。
7. 非业务故障中断后续处理，返回 503 和已完成进度；此前确认提交的来源保留，可重试原文件。

不保证整批原子性。提交过程中断线时当前条目的实际提交结果可能不确定；报告的 storage_error 表示未确认成功，而不承诺数据库一定无此记录，重试按地址去重。

## 限制与安全

文件最大 1 MiB（包含全部字节）；最多 1000 个 outline（包括文件夹），XML 最深 32 层（opml 为第 1 层），全部元素最多 10000 个（包含 head）。
defusedxml 禁止 DTD、实体声明和外部引用，按 XML 声明处理编码；UTF-16 不能绕过检查。
HTTP 按实际流量检查大小，不依赖 Content-Length。不支持 multipart，客户端直接提交 XML 文件内容。
报告仅给候选项顺序、状态、原因码和可用的来源 ID，不回显原始标题和地址。
