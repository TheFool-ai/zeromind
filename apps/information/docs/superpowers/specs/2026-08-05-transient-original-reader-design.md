# 临时原文阅读设计

## 背景

内容详情页当前直接把第三方原文 URL 放入 iframe。实际内容源（尤其 X）通过 `X-Frame-Options: SAMEORIGIN` 和 CSP `frame-ancestors` 禁止跨站嵌入，因此浏览器会稳定拦截。BestBlogs 采用元信息与正文分离的两段式加载：先渲染元信息，再异步加载提取后的正文并在站内呈现。

## 方案

采用临时正文读取，不绕过第三方安全头，也不持久化原文：

1. 详情接口继续返回引用、RSS 元数据和分析结果。
2. 新增受认证的 `GET /api/v1/references/{id}/content` 接口。
3. 接口通过现有 `ContentResolver` 实时请求原文，执行 SSRF、重定向、内容类型、超时和 5 MiB 大小限制，然后返回提取后的纯文本及来源元数据。
4. 前端在详情元信息成功后再请求正文，并在原文栏内以站内阅读样式渲染。
5. 提取失败时保留 RSS 标题、摘要、作者和“新窗口打开原文”入口，并允许重试。

## 安全与数据边界

- 不把访问令牌放入 iframe 或查询字符串。
- 不向浏览器返回第三方 HTML、脚本、样式或事件处理器。
- 不代理图片及其他子资源。
- 不新增正文数据库字段、缓存表或迁移。
- 正文仅存在于后端请求、JSON 响应和当前浏览器内存中。

## 验证

- 后端覆盖成功读取、引用不存在、解析失败和服务未配置。
- 前端覆盖元信息先展示、正文加载、正文失败回退和外链。
- 运行后端测试、Ruff、mypy、前端测试、类型检查和生产构建。
- 部署后用真实引用验证接口、桌面布局和移动端切换。

## 非目标

- 不尝试规避 `X-Frame-Options` 或 CSP。
- 不引入无头浏览器、正文持久化、图片代理或沉浸式翻译。
