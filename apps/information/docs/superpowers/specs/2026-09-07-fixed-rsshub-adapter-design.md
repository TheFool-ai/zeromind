# Fixed RSSHub Adapter Design

**Status:** Approved in conversation on 2026-09-07

## 1. Goal

Simplify RSSHub support from a runtime-managed business module into a fixed deployment
dependency. ZeroMind continues to accept instance-independent `rsshub://` subscription
addresses, but resolves them through one RSSHub base URL supplied by deployment
configuration.

This change removes multi-instance registration, activation, database-backed credentials,
and the RSSHub administration UI. It does not change normal HTTP/HTTPS subscriptions,
OPML support, feed polling, ingestion, or downstream analysis behavior.

## 2. Deployment Model

The bundled Compose deployment owns one private RSSHub service at
`http://rsshub:1200`. The backend worker receives that address through:

```text
ZEROMIND_RSSHUB_BASE_URL=http://rsshub:1200
```

RSSHub route-provider credentials such as `TWITTER_AUTH_TOKEN`, cookies, and proxy
settings remain environment variables of the `rsshub` container. ZeroMind does not read,
store, encrypt, expose, or manage those credentials.

The RSSHub service remains private to the Compose network. Its port is not published to
the host. `ZEROMIND_RSSHUB_PRIVATE_HOSTS=rsshub` remains the explicit network-policy
allowlist entry that permits scheduled feed fetching to reach the private Compose DNS
name.

## 3. Architecture

RSSHub URL resolution becomes a subscriptions infrastructure concern:

```text
Subscription feed_url
  rsshub://twitter/user/example
          |
          v
FixedRSSHubResolver
  base URL from Settings
          |
          v
http://rsshub:1200/twitter/user/example
          |
          v
FeedClient -> Ingestion -> Outbox -> Analysis workflows
```

The resolver lives under the subscriptions package because it adapts a supported
subscription address into a fetchable HTTP URL. It has no repository, service, ORM model,
or runtime management API.

The task bootstrap constructs the resolver directly from `Settings.rsshub_base_url`.
Application startup no longer constructs an RSSHub service or registers an RSSHub HTTP
router.

## 4. Configuration Contract

`Settings` adds:

```python
rsshub_base_url: str = "http://rsshub:1200"
```

The value must be an absolute HTTP or HTTPS URL with a host. It may contain a path prefix,
but may not contain credentials, query parameters, a fragment, whitespace, or path
traversal segments. Trailing slashes are removed before routes are joined.

Compose explicitly supplies `ZEROMIND_RSSHUB_BASE_URL`, even though the default matches
the bundled service. Operators using a different fixed deployment override only this
environment variable.

Invalid base URL configuration fails when the worker constructs the resolver. Ordinary
HTTP/HTTPS subscriptions do not require an RSSHub request and are returned unchanged by
the resolver.

## 5. Resolver Behavior

The fixed resolver preserves the existing external subscription contract:

- HTTP and HTTPS feed URLs pass through unchanged.
- `rsshub://` locators are validated and normalized through `FeedAddress`.
- The locator route and existing non-authentication query parameters are appended to the
  configured base URL.
- Locator-provided `key` and `code` query parameters are removed so credentials cannot be
  persisted in subscription URLs or smuggled into requests.
- No access key or MD5 code is generated by ZeroMind.

Examples:

```text
rsshub://twitter/user/vista8
  -> http://rsshub:1200/twitter/user/vista8

rsshub://twitter/user/vista8?mode=full&key=secret
  -> http://rsshub:1200/twitter/user/vista8?mode=full
```

The resolver is deterministic and performs no I/O. The polling flow continues to use the
existing network policy, redirect validation, timeouts, and response-size limits in
`FeedClient`.

## 6. Removed Product Surface

The following runtime-managed RSSHub capabilities are removed:

- RSSHub instance domain objects and authentication modes;
- credential encryption and database storage;
- in-memory and SQLAlchemy RSSHub repositories;
- instance create, list, update, activate, and delete services;
- `/api/v1/rsshub/instances` endpoints;
- the `/rsshub` frontend page, navigation item, client type, and UI tests;
- bootstrap dependency injection for `RSSHubInstanceService`.

The `rsshub://` format, subscription UI guidance, FeedAddress validation, OPML handling,
and RSSHub-based feed polling remain supported.

## 7. Database Migration

A new forward Alembic migration drops the obsolete `rsshub_instances` table and its
partial unique index. Existing migration history remains unchanged so deployed databases
can upgrade normally.

The migration is intentionally destructive for legacy RSSHub instance records: the new
deployment setting replaces them, and no record has a meaningful destination in the new
model. Downgrade recreates the former empty schema but cannot restore deleted instance
data.

Alembic metadata registration no longer imports the removed RSSHub ORM model.

## 8. Error Handling and Security

- An invalid `ZEROMIND_RSSHUB_BASE_URL` raises a stable configuration `ValueError` before
  a resolved URL is fetched.
- A malformed `rsshub://` locator continues to be rejected by `FeedAddress` at subscription
  creation or OPML preview time.
- RSSHub fetch failures continue through the existing subscription failure accounting and
  exponential backoff.
- Route-provider secrets remain isolated inside the RSSHub container and are not returned
  by ZeroMind APIs.
- The fixed private host remains explicitly allowlisted only for scheduled feed fetching.

## 9. Documentation and Operations

The project README and subscription domain documentation will describe RSSHub as a fixed
deployment adapter. Setup instructions will no longer ask users to register an instance in
the UI. They will instead explain that Compose starts RSSHub automatically and that
provider-specific environment variables belong to the RSSHub service.

Historical implementation plans and specifications remain unchanged as records of earlier
decisions. Current authoritative documentation is updated to reflect the new behavior.

## 10. Testing

Tests will cover:

- base URL normalization and rejection of unsafe configuration;
- passthrough of HTTP/HTTPS feed URLs;
- deterministic resolution of `rsshub://` locators, including path prefixes and query
  preservation;
- removal of locator-provided `key` and `code` parameters;
- polling with the settings-backed resolver;
- absence of the RSSHub API router and frontend navigation/page;
- migration upgrade dropping the legacy table and downgrade recreating its schema;
- rendered Compose configuration containing the fixed base URL and private RSSHub service;
- existing subscription, OPML, network-policy, feed polling, and frontend regression tests.

## 11. Non-Goals

This change does not add:

- multiple RSSHub instances;
- runtime instance switching or health management;
- failover or load balancing;
- per-subscription RSSHub selection;
- ZeroMind-managed RSSHub access authentication;
- a public RSSHub port;
- dynamic editing of deployment configuration from the UI.
