# 单列信息流设计

## 目标

将“信息流”从自适应多列卡片改为单列编辑精选布局，使用户能够沿固定阅读路径快速判断内容是否值得打开，同时保留现有筛选、分页、状态和详情能力。

## 已确认方向

采用可视化方案 A“编辑精选”。页面以标题和摘要为视觉中心，评分作为右侧辅助决策信号，不增加新的业务字段或接口。

## 页面结构

- 页面标题与说明保持不变。
- 筛选区保留通过/拒绝、最低分数、分类、订阅源和日期范围，并收紧为轻量工具栏。
- 信息流主体居中，桌面端最大宽度约 900px。
- 每条内容使用横向编辑条目，不设置固定高度；条目之间以细分隔线区分，不再呈现为独立网格卡片。
- 条目左侧依次展示状态、来源、发布时间、标题、一句话摘要、主分类和标签。
- 综合评分固定在条目右上区域；人工改判标识与状态位于同一元信息层级。
- 详情链接继续由标题承载，原文入口保留在条目底部操作区。
- “加载更多”、加载态、空态和错误态保持现有行为。

## 响应式行为

- 桌面端内容和评分采用主内容加窄评分列。
- 窄屏下改为单一内容列，评分移到标题上方的元信息行，避免压缩标题与摘要。
- 筛选区在中等宽度下分为两列，在手机宽度下变为一列。
- 标签允许换行，长标题和摘要自然增高，不截断关键内容。

## 组件与数据流

- 继续使用现有 `AnalysesPage`、`AnalysisCardView`、React Query 查询和筛选状态。
- 将列表容器从多列网格语义调整为单列信息流语义，并重组条目内部 DOM，以便评分列和移动端顺序通过 CSS 控制。
- 不修改后端 API、查询参数、游标分页、路由或 `AnalysisCard` 数据类型。
- 所有错误继续通过 `ErrorNotice` 呈现，不改变认证和重试策略。

## 视觉规则

- 延续现有纸张色、墨色、强调红色和衬线标题，不引入新设计系统。
- 减少外框、阴影和悬浮位移；使用留白、排版和分隔线建立层级。
- 综合评分仍使用强调色，但尺寸低于页面标题，不抢占阅读焦点。
- hover 只增强标题或条目背景反馈，不产生位置跳动。

## 验证

- 更新组件测试，确认标题、摘要、来源、评分、标签、详情链接和原文链接均正确呈现。
- 保持筛选与加载更多测试通过。
- 运行 TypeScript 类型检查、前端测试和生产构建。
- 在桌面与手机宽度下进行浏览器视觉检查，确认单列宽度、评分位置、换行和筛选布局。

## 非目标

- 不调整分析详情页或内容引用页。
- 不增加排序、收藏、搜索或无限滚动。
- 不修改分析评分规则或后端数据模型。
